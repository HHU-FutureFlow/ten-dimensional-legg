# 工程地图 · Project Graph Demo v0.4

用功能块、信号端口和连线记录工程结构。人通过浏览器编辑，agent 通过 CLI 编辑同一份图。新工程从空白画布开始，也可以显式打开十维轮腿 LQR 示例。

核心是通用节点图编辑器，可描述软件功能、硬件接线或其他流程；LQR 专用内容只在示例中。现版采用有向输入/输出连接，硬件的双向总线可以先拆成收发关系表达。

代码仓库：[KazeYamu/project-graph](https://github.com/KazeYamu/project-graph)（当前为私有仓库）。

这是一个可以独立移动的目录。运行工具不需要机器人固件、Codex、EmberProbe 或某个开发者电脑上的固定路径。

## 启动

需要 **Node.js 24 或更高版本、npm、现代浏览器**。本轮构建环境为 Node.js 24.14.0、npm 11.9.0。首次安装依赖需要网络，之后运行已构建应用不需要访问外部服务。

在本目录执行：

```sh
npm ci
npm run build
npm start
```

固件仓库包含上游 Project Graph `bd8309d` 的源码快照。从固件仓库进入此目录即可启动。服务运行后，可在另一个终端用以下命令导入随仓库发布的当前底盘地图。

```sh
npm run graph -- import --file ../十维轮腿底盘工程地图.graph.json
```

也可在浏览器导入[底盘工程地图](../十维轮腿底盘工程地图.graph.json)。导入会建立可编辑副本。

打开终端显示的地址，默认是 [http://127.0.0.1:4317](http://127.0.0.1:4317)。终端按 Ctrl+C 停止服务，已保存数据保留。

Windows 可双击 `scripts/start.cmd`：检查 Node 和锁文件依赖、按需安装、构建、启动服务并打开浏览器。更新代码后即使已有 node_modules，也会检查新增依赖及锁文件变化。也可单独执行 `npm run setup`。该入口与上面的 npm 命令使用相同服务。

前端开发时可在一个终端执行 `npm run server`，另一个执行 `npm run dev`。开发代理默认连接本机 4317 端口；如果使用其他端口，给两个进程设置相同的 `GRAPH_PORT`。队友直接访问构建后的服务即可。

## 本地编辑

1. 首次打开自动创建一个空白工程；点击“创建第一个功能块”或工具栏“添加节点”。
2. 在右侧填写一句话概述，再按“接收什么 / 怎么处理 / 输出什么 / 判定与结果”编辑功能说明，点击“保存节点修改”。参数 JSON 位于进阶区域。
3. 点击节点详情的“接口”，添加输入/输出端口；点击端口名称编辑类型、维度、单位、坐标系和显示顺序。
4. 从节点右侧输出圆点拖到另一节点左侧输入圆点，创建连接。选择连线可编辑信号名称、类别、条件和样式。
5. 节点可以自由拖动；Ctrl 多选、Shift 框选；工具栏可开关网格吸附。使用“适应画布”查看全图。
6. 选择一条连线后，点击连线标签上的 `+` 增加中间走线点；拖动控制点调整路径，右键删除该点。右侧也可以恢复默认走线。
7. 选中节点后点击“分组”，可以收起/展开、整体移动、调整分组尺寸；取消分组保留成员节点。

默认贝塞尔曲线，也支持圆角折线和直线。中间走线点用于整理线路；首版不自动避开所有节点。

## 块配色

选中功能块、说明板或分组，点击工具栏「外观」，也可以右键点击画布上的块。可以直接应用预设，或分别用取色器和 `#RRGGBB` 设置背景、标题栏及边框。文字根据对应背景自动选择明暗。展开的分组使用半透明底色，便于阅读其中的连线。

用 Ctrl 或框选选中多个块后打开「外观」，只会应用修改过的颜色项。单项「默认」会清除该颜色的自定义值。「恢复全部默认」会清除所选块的全部自定义颜色，说明板恢复到属性面板中的默认展板颜色。

配色随布局保存，支持撤销、导入导出和团队同步。更新到 v0.4 后重启服务即可为已有 v2 图配色。

## 说明板和可理解的节点说明

工具栏“说明板”创建一块**没有输入输出端口**的展板。可写标题和 Markdown 正文，支持段落、列表、表格、行内代码及链接；不执行原始 HTML，不自动加载外部图片。

- 拖标题移动，选中后拖边角调尺寸；右侧也能填写宽高、颜色和所属分组。
- 标题双击可放大阅读，正文可选中文字、滚动阅读。说明板不连线，也不拥有功能子视图。
- 正文、尺寸、颜色随项目保存、导出、导入和共同编辑，agent 仍使用相同节点事务。

每个功能块可以填写四类结构化说明：

| 字段 | 应该回答 |
| --- | --- |
| 接收 | 从哪里得到什么量，物理或业务含义是什么，必要时说明单位。 |
| 处理 | 做哪些步骤、怎样改变输入、这一步有什么作用。 |
| 输出 | 给下一块什么结果、哪些字段会改变。 |
| 判定与结果 | 按优先级逐条写“什么条件 → 什么结果”；无分支可留空。 |

卡片先显示简明内容，点击“完整说明”展开全部判定。没有子视图的普通节点双击标题可放大阅读；有子视图时仍进入下一层。编写示例的规则见 [说明写作指南](docs/WRITING_GUIDE.md)。

连线区分数据传递、条件结果、虚线状态转移和力/力矩。阶段选择只取符合条件的候选路径，不因多条线同时存在就把结果相加。

新版 LQR 示例增加了 6 块阅读/符号/状态展板，解释 S0～S7、PD、LQR、力与力矩、坐标系和覆盖优先级；原有 43 个功能/边界节点全部重写了结构化说明。纯恢复 PD 改为从腿角目标与反馈接收数据，不再误接原始 LQR 力矩。

## 源码位置与多层子视图

- 节点卡片直接显示 `文件名:起始行–结束行` 和函数名。悬停查看完整相对路径，多处关联显示数量。
- 点击卡片中的文件位置，右侧直接切到“关联资料”，可以查看并复制完整定位。关联为可选项，也可以记录原理图或接口手册；行号由维护者填写，不自动扫描源码。
- 普通功能块可在右侧点击“创建子视图”。已有子视图时，点击卡片“进入子视图”或双击节点标题进入。
- 每层使用独立画布和保存视角，顶部面包屑随时返回上层；左侧导航只显示当前层的节点与分组。
- 新子视图自动创建“来自上层的输入”和“返回上层的输出”。父节点输入在内部表现为边界输出，父节点输出在内部表现为边界输入。
- 上层端口的名称、类型、维度、单位和坐标系自动同步到边界端口；在边界端口详情可以“转到上层端口”。边界节点/契约不单独删除，通过上层端口或子视图管理。
- 子视图中的功能块也可以继续创建子视图。分组用于同一画布内整理，子视图用于进入独立的详细逻辑空间。
- 保存、导出和团队共编覆盖整个工程中的所有层级。复制功能块只复制当前节点及其端口，不深复制内部子视图；删除拥有子视图的节点会明确确认级联影响。
- 属性草稿请在切换节点/视图前保存。外部修改推进 revision 时，当前选中节点的草稿保留，过期提交会提示冲突。

新版 LQR 示例有三层：**工程总览 → 模式处理 → 模式判定与状态转换**。它手工记录 S0 观测驻留与位形分选、S1～S7 转移、恢复 PD、交接混合、后续悬空覆盖和最终输出闸，并为各块补充了代码范围。

此次按使用者要求采用 **v2 数据格式，不兼容或迁移初版 v1**。默认使用 `data/v2/`，初版 `data/` 中的旧文件保留。更新后先关闭旧服务、重新启动并打开新版 LQR 示例；若 `.env` 配置过 `GRAPH_DATA_DIR=./data`，改成 `./data/v2` 或另一个空目录。不要把旧服务返回的数据与新版前端混用。

v0.3 保留 v2 文件格式，扩展结构化说明、说明板和状态转移线；浏览器/CLI 同时检查服务能力。原有保存图不自动改写；若要看新文案和展板，请重新点击“打开 LQR 示例”创建新版副本。

节点移动在拖动结束时保存，属性在明确提交时保存。画布操作和属性提交都显示保存状态；出现错误或冲突时需处理后重试。不要把尚未提交的属性草稿当作已保存数据。

## 导出给队友

- 点击“导出共享”，下载一个 `.graph.json`，包含节点、端口、连接、说明及布局。
- 队友启动自己的实例，点击“导入 JSON”选择文件，形成新的独立工程身份，避免覆盖已有工程。
- 源码不在队友电脑上时，图仍能正常打开与编辑。
- 发送 JSON 是分享副本。后续需要交换新版本，或者让双方连接同一个服务共同编辑。

导出文件不包含服务凭据、磁盘数据目录或机器源码绑定。维护者自己写入说明/参数中的内容仍会随图导出，分享时自行确认内容范围。

## 团队基础共同编辑

在一台能被队友访问的电脑上运行一个服务，所有浏览器和 agent 连接它。服务端电脑需在使用期间保持运行。

复制 `.env.example` 为 `.env`，修改：

```dotenv
GRAPH_HOST=0.0.0.0
GRAPH_PORT=4317
GRAPH_DATA_DIR=./data/v2
GRAPH_ACCESS_TOKEN=replace-with-at-least-16-characters
```

运行 `npm start`，队友访问 `http://服务端电脑的局域网地址:4317`，输入相同访问令牌。根据主机实际网络配置允许该端口入站。

单机默认仅监听 `127.0.0.1`。非回环监听强制要求至少 16 字符的令牌，API 查询、写入和事件通知都进行认证。令牌仅保存在浏览器当前标签页会话中；不写入工程导出文件。跨互联网部署应放在 HTTPS 入口后；本 demo 不包含公网部署或账号管理。

基础共同编辑的行为：

- 节点移动结束或属性提交后，其他窗口自动更新；断线重连重新读取项目。
- 每次事务带当前 revision。同版本并发提交发生冲突时，拒绝过期修改，不自动合并。
- 右侧尚未提交的属性草稿保留；如果图已有更新，先检查草稿，选择重读后再修改/提交。
- 不显示队友光标，不逐帧广播拖动，不提供同时输入同一段文字的合并。
- 同一个数据目录只允许一个服务实例写入。多人连接它，而不是各开一个服务共同指向数据目录。
- actor 仅表示修改来源，不是独立用户身份或权限系统。

## 存储、恢复与限制

默认数据在本目录 `data/v2/`；相对 `GRAPH_DATA_DIR` 以工具目录为基准，绝对目录也可由部署者配置。源码引用使用逻辑 rootId 和相对路径。

```text
data/v2/
  <projectId>.graph.json       当前权威项目
  .writer.lock                 单实例写入锁
  backups/<id>.<revision>.json  成功提交前的恢复备份
```

建议定期导出重要工程，或停止服务后备份整个数据目录。恢复历史版本时，把备份通过“导入 JSON”导入成独立工程进行核对。

不要在服务运行时直接覆盖活动项目 JSON。检测到外部修改时服务会拒绝继续覆盖；停止服务核对文件，再重启或导入备份。异常退出留下的写入锁只有在确认原进程不在时才自动清理；损坏锁需要管理员确认没有其他写入服务后处理。

撤销/重做只支持当前服务会话的最多 30 笔历史，且只允许操作全局栈顶、由当前 actor 提交的事务。服务重启后图保留，撤销栈清空。请求重试去重也仅在当前服务会话的最近 300 个 requestId 内生效；断线/重启后先查询 revision，不盲目重放。

项目/事务上限 8 MB。共享相对源码引用只显示与复制定位信息，不读取任意本机源码文件、不自动更新行号。工具不执行节点公式、不生成或修改固件、不访问机器人硬件。

## Agent 使用

先读 [通用 agent 指南](docs/AGENT_GUIDE.md)，配套入口为 [project-graph skill](skills/project-graph/SKILL.md)。skill 随目录交付，不自动安装到任何 agent 的全局配置。

```sh
npm run graph -- list
npm run graph -- create --title "新的工程"
npm run graph -- create --title "LQR 示例" --lqr
npm run graph -- inspect --project PROJECT_ID
npm run graph -- inspect --project PROJECT_ID --scene mode-detail
npm run graph -- validate --file ./examples/lqr.graph.json
npm run graph -- apply --project PROJECT_ID --file ./examples/patches/describe-lqr.json --dry-run
npm run graph -- export --project PROJECT_ID --out ./shared.graph.json
```

提交前根据实际项目修改示例补丁的 `baseRevision` 和 `requestId`，再移除 `--dry-run` 执行。创建空白项目后不能应用引用 `lqr` 节点的示例补丁。

连接团队服务时配置 `GRAPH_URL` 和 `GRAPH_ACCESS_TOKEN`，或通过 `--url` 指定地址。凭据不放进补丁或命令行参数。CLI 正常输出 JSON，错误输出 JSON 到 stderr 并返回非零退出码。参考 [接口说明](docs/API.md) 和 [数据格式](docs/DATA_FORMAT.md)。

## 容器复现入口

需要 Docker/Compose。先在 `.env` 设置自己的共享令牌，再执行：

```sh
docker compose up --build -d
docker compose down
```

使用命名卷保存 `/app/data`，停止/重建容器不会主动删除卷。`docker compose down -v` 会删除数据卷，日常停止使用不带 `-v` 的命令。当前交付环境没有 Docker，容器构建和重建恢复尚未实测，详见验证记录。

当前格式的数据写在卷内 `/app/data/v2`。

## 验证与开发入口

```sh
npm test
npm run check
npm run build
npm run test:ui
npm run test:portable
```

浏览器测试使用隔离临时目录，不修改实际 `data/`；Windows 优先使用安装的 Edge/Chrome，其他环境使用 Playwright Chromium。需要时执行 `npx playwright install chromium`，也可设置 `PLAYWRIGHT_EXECUTABLE_PATH` 指向浏览器可执行文件。

便携检查会把源码复制到另一个含空格的临时目录，从锁文件全新安装依赖、重新构建并启动服务，核对示例导入导出；需要网络或可用的 npm 缓存，不复制现有 node_modules。

LQR 示例可通过 `node scripts/create-examples.mjs` 重新生成。它是人工整理的数据，不是自动源码分析。构建通过锁定依赖及分包复现，未修改任何第三方包源码。

实际通过项、失败修复与平台限制记录在 [验证记录](docs/VERIFICATION.md)。构建 agent 的接手入口为 [整体实施方案](IMPLEMENTATION_PLAN.md)，不能把其中旧阶段规划当作已验证能力。
